# 機能仕様書（草案）— Unified-File-Search-Tool

## 1. 機能一覧
1. ディレクトリ指定
2. ファイル列挙（検索前一覧）
3. 検索（内容検索）
4. 検索結果一覧（マッチしたファイルのみ）
5. マッチ箇所管理（マッチ箇所単位のプルダウン）
6. プレビュー表示（現物に近い再構成 + 強調表示）
7. ページ/シート切替（該当時のみ有効）
8. ズーム（拡大/縮小/等倍）
9. フルロード（選択ファイル全体プレビュー）
10. メタデータ取得（作者/作成日：Officeプロパティ）

## 1.1 実装構成（機能別フォルダ分割）
実装は機能ごとにフォルダ/ファイルを分割し、共通処理は共通モジュールに集約する。

- 例（概念）
  - アプリ/UI: 画面、状態、イベント、描画
  - 列挙: ディレクトリ走査、対象ファイル判定
  - 検索: 一致判定、除外語、50件打ち切り、進捗通知
  - 変換/抽出: 形式別のテキスト抽出・HTML再構成
  - プレビュー: マッチ箇所の強調、ページ/シート切替、ズーム、フルロード
  - メタデータ: Officeプロパティ取得
  - 共通: 文字正規化、例外処理、ログ、設定、ユーティリティ

## 1.2 設定（Config）
- 設定はXMLで管理する（例: `Config/config.xml`）
- 大容量警告の閾値、ログレベル等の値は設定から参照し、コード内にマジックナンバーを持たない

### 1.2.1 設定ファイルの解決順（ポータブル優先）
1. 実行ファイルと同じフォルダ配下の `Config/config.xml`
2. ユーザー領域（例: `%LOCALAPPDATA%\Unified-File-Search-Tool\Config\config.xml`）

※実行ファイル配置先に書き込み権限がない場合はユーザー領域へフォールバックする。

## 2. 入出力
### 2.1 入力
- 対象ディレクトリ
- 検索語
- 検索条件（表層ON/OFF）
  - 拡張子フィルタ
  - 大小文字区別
  - 正規表現
  - 全文一致 / 一部一致
- 詳細設定
  - 除外語
  - サブフォルダ検索有無
  - ファイルサイズ上限
  - 更新日範囲

### 2.2 出力
- 検索前一覧（対象ファイル一覧）
- 検索後一覧（マッチファイル一覧）
- マッチ箇所プルダウン（マッチ箇所単位）
- プレビュー（強調表示 + 画像/表を含む再構成表示）

## 3. 一覧（左ペイン）機能仕様
### 3.1 検索前一覧
- 指定ディレクトリ配下のファイルを一覧表示する
- サブフォルダ検索の有無に応じて列挙対象を変える（詳細設定）

### 3.1.1 拡張子の収集と絞り込み
- 対象ディレクトリの列挙結果から「存在する拡張子一覧」を生成し、UI（拡張子フィルタのポップアップ）へ提供する
- 拡張子フィルタでチェックONの拡張子のみ、一覧表示・検索対象とする
- ディレクトリ変更時は拡張子一覧を再生成する

### 3.2 検索後一覧
- 検索語にマッチしたファイルのみ表示する

### 3.3 カラム挙動
- Path列の右クリックメニュー
  - 「ファイルを開く」: OS既定アプリで開く
  - 「Pathをコピー」: クリップボードへフルパスをコピー
- 検出数
  - 1ファイルあたり最大50件までカウント
  - 51件以上が見つかった時点で当該ファイルの追加読み取りを打ち切る
  - 表示は `50>`
- Infoチップ
  - 作者・作成日はOfficeのプロパティを取得して表示する
    - 作者: `Last Modified By` を優先し、取得できない場合は `Author` を用いる
    - 作成日: `Created` を優先し、取得できない場合は `Modified` を用いる

## 4. 検索機能仕様
### 4.1 一致判定
- 大小文字区別: ONの場合はケースセンシティブ
- 正規表現: ONの場合は正規表現で一致判定
- 全文一致 / 一部一致
  - 全文一致: 対象テキスト単位で完全一致
  - 一部一致: 対象テキスト内に含まれる場合一致

※対象テキスト単位（段落/行/セル等）はファイル形式ごとに定義し、UI側では「マッチ箇所」として統一的に扱う。

### 4.1.1 正規表現（リッチ入力支援の反映）
- UIで挿入されたパターン（例: `.*` 等）も、ユーザーの手入力も、同一の検索式として扱う
- 正規表現のオプション（例: 複数行等）が指定されている場合は、それを一致判定に反映する

#### 4.1.1.1 オプション（3つに固定）
- Ignore case（大小無視）
- Multiline（`^`/`$` を行単位にする）
- Dot matches newline（`.` が改行も含む）

※実装は言語/ライブラリの正規表現フラグにマップする（例: Pythonなら `IGNORECASE` / `MULTILINE` / `DOTALL`）。

#### 4.1.1.2 パターン挿入ボタン（少数精鋭）
UIの挿入ボタンは、以下の文字列を検索式（単一入力欄）へそのまま挿入する。

- `.*`
- `\\s*`
- `\\d+`
- `^`
- `$`
- `|`
- `(...)`
- `(?:...)`

### 4.2 除外語
- 詳細設定で指定された除外語が含まれるマッチ箇所は結果から除外する

### 4.3 50件打ち切り
- 1ファイルにつきマッチ検出は最大50件で打ち切る
- 目的: 性能確保および「件数が多すぎるファイルに時間を使いすぎない」UX

### 4.4 堅牢性（落ちない）
- 例外や読み取り不能が発生してもアプリはクラッシュしない
- エラー発生ファイルはスキップし、検索全体は継続する

### 4.4.1 中断（ESC）
- 検索処理はESCキー操作で中断できる
- 中断時は速やかにバックグラウンド処理を停止し、UIは操作可能な状態へ戻る

### 4.5 性能・メモリ設計方針
- 検索/抽出処理は原則ストリーミングまたは遅延処理を行い、不要な全読み込みを避ける
- 大量ファイル時もUI応答を維持するため、処理はバックグラウンドで実行し、進捗を通知する
- キャッシュは上限を持ち、肥大化しない（必要に応じて破棄/再生成）

## 4.6 ロギング仕様（機能ごと）
- 各機能（列挙/検索/抽出/プレビュー/メタデータ/UI）でログを出力する
- 1処理単位（例: 検索1回）で追跡できるよう、処理開始/終了、対象件数、所要時間、エラーを記録する
- 例外発生時は原因特定に必要な情報（対象ファイル、処理段階、例外情報）を記録する

### 4.6.1 出力先/ファイル分割
- ログはログ用フォルダ（例: `logs/`）に出力する（ポータブル運用を優先）
- 機能フォルダ単位でログファイルを分割し、機能内の形式別実装（pptx/xlsx/docx/pdf/txt等）は単一ログに集約する
  - 例: `search.log`, `enumeration.log`, `preview.log`, `metadata.log`, `ui.log`

### 4.6.1.1 ポータブル運用時の保存先
- 原則: 実行ファイルと同じフォルダ配下の `logs/` に出力する
- 書き込み不可の場合: ユーザー領域（例: `%LOCALAPPDATA%\Unified-File-Search-Tool\logs\`）へフォールバックする

### 4.6.2 保持方針（上限1000行 + FIFO）
- 各ログファイルは最大1000行まで保持する
- 1000行を超える場合はFIFO方式で古い行から削除し、最新1000行を保持する

### 4.6.3 ログレベル
- Information / Warning / Critical を必須とする
- 必要に応じて Debug を用意し、通常運用では無効化できる

### 4.6.4 ログフォーマット（機能横断で統一）
- 機能別にファイルが分かれていても、ログ1行の書式は共通とする
- 1行=1イベントで、**JSON Lines（JSONL）** 形式で出力する（形式はこれに固定する）
- 最低限の共通フィールド（例）
  - timestamp（ISO 8601）
  - level（Information/Warning/Critical/Debug 等）
  - feature（search / enumeration / preview / metadata / ui 等）
  - event（start/end/skip/error 等）
  - message
  - correlation_id（例: search_run_id）
  - file_path（関係する場合のみ）
  - elapsed_ms（計測できる場合）

## 5. マッチ箇所（プルダウン）仕様
- 粒度: マッチ箇所単位
- 表示項目（案）
  - ファイル名
  - 位置情報（PDF: ページ、Excel: シート、PowerPoint: スライド、Word: セクション/ページ相当、Text/MD: 行番号相当）
  - 前後の簡易抜粋（可能であれば）

※実際にどこまで位置情報を保証できるかはファイル形式ごとに実装方式に依存する。

## 6. プレビュー仕様
### 6.1 表示方針
- 目標: 画像や表も含めHTMLで再構成し、現物に近い表示を提供する
- マッチした文言は強調表示し、視認性を上げる（誇張できる）

### 6.1.1 ページ相当
- PDF / Word / PowerPoint は「1ページ相当」の単位を持つ
  - PDF: ページ
  - Word: 1ページ相当
  - PowerPoint: スライド（= 1ページ相当）

### 6.2 フルロード（選択ファイル全体プレビュー）
- ユーザーがフルロード操作を行った場合、選択されたファイルのみ全体をプレビュー表示する
- 全体表示中も、マッチ箇所の強調表示は維持する
- フルロードは「プレビューの表示対象」を切り替える操作であり、検索結果（マッチ箇所の集合）自体は変更しない
- 対象ファイルが大容量閾値を超える場合は警告を表示し、ユーザーがOKした場合のみ読み込む
 - フルロード後は、スクロールバーでファイル全体を連続的に閲覧できる

### 6.3 ページ/シート切替
- 通常は無効（グレーアウト）
- 複数ページ/複数シートにマッチがある場合のみ有効
- 切替操作により、プレビュー表示を該当ページ/シートへ遷移させる

### 6.4 ズーム
- 拡大（＋）、縮小（－）、等倍（100%に戻す）を提供
- ズームはプレビュー表示されている全コンテンツに適用される

## 6.5 検索進捗表示
- 検索中は進捗をプログレスバーと数値で表示する
- 進捗率（0–100%）は、調査対象ファイルの総ファイルサイズ（bytes）を母数にした割合とする
- `処理済みbytes/総bytes` と `処理済み/総数` を表示する

### 6.5.1 進捗の加算ルール（仕様の明確化）
- `処理済みbytes` は、原則として「ファイル単位の完了」で加算する
  - 50件打ち切り（1ファイル最大50件）やスキップ（エラー/除外条件）でも、当該ファイルの処理は完了扱いとしてファイルサイズ分を加算する

## 7. 形式別の取り扱い（方針レベル）
- `.txt`/`.md`: テキストとして表示し、マッチ箇所をハイライト
  - 改行の扱い: `\n` / `\r\n` / `\r` のいずれも改行として扱い、内部表現は `\n` に正規化する（表示上は改行されていればよい）
  - 文字コード: 可能な限り自動判別・変換して表示し、採用した文字コードをUI右下に表示する
    - 優先順（整理）: **CP932（Windows-932）** → UTF系（UTF-8/UTF-16等） → それでも不可なら文字化けを許容して表示継続
  - 大容量時: 閾値を超える場合は警告を表示し、OKした場合のみ読み込む
- `.log`: テキストとして表示し、制御文字を含む場合は表示用に無害化してからハイライト
  - 改行の扱い: `\n` / `\r\n` / `\r` のいずれも改行として扱い、内部表現は `\n` に正規化する（表示上は改行されていればよい）
  - 無害化ルール: 改行（上記）以外の制御文字は取り除く
  - 整形ルール: 各行は左詰め（行頭の空白/タブを除去）にする
  - 文字コード: 可能な限り自動判別・変換して表示し、採用した文字コードをUI右下に表示する
    - 優先順（整理）: **CP932（Windows-932）** → UTF系（UTF-8/UTF-16等） → それでも不可なら文字化けを許容して表示継続
  - 大容量時: 閾値を超える場合は警告を表示し、OKした場合のみ読み込む
- Office（`.pptx`/`.xlsx`/`.docx`）: プロパティ取得（作者/作成日）を行い、本文・表・画像を可能な範囲でHTML再構成して表示
- `.pdf`: テキスト抽出に加え、表示はPDFに近い見た目を目標にHTMLで再構成し、マッチ文字列を強調

※「ほぼ現物」を満たすための具体手段（ライブラリ選定、レンダリング方式、位置合わせ）は実装フェーズで検討し、ここは要件として固定する。
